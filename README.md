# xvpn

Свой VPN на Xray-core. Один установщик подходит для разных схем: один сервер, несколько серверов или каскад через Россию для обхода белых списков, с резервом выходов и входов. Ключами управляют командой `xvpn` по SSH. Telegram-бот с мини-аппом ставится по желанию.

Xray ставится официальным скриптом XTLS, остальной код лежит в этом репозитории.

## Как устроено

У каждой схемы есть **главный сервер**: на нём база ключей, подписки и синхронизация. Остальные серверы подключаются к нему по **коду подключения**, который их установщик показывает в конце.

| Роль | Что делает | Команда |
|---|---|---|
| Главный сервер | ключи, подписки, бот; сам тоже раздаёт VPN | `install.sh server` (бот спросит) или `install.sh panel` (с ботом) |
| Сервер-выход | раздаёт VPN, работает выходом для мостов | `install.sh node` |
| Мост (РФ) | вход каскада: клиенты → мост → выходы, российские сайты напрямую | `install.sh bridge` |

Без аргументов `install.sh` показывает меню.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/duboshin52/xvpn/main/install.sh)
```

Нужна Ubuntu 22.04 или 24.04 и права root.

### Если xvpn уже стоит

Перед установкой установщик проверяет сервер. Если xvpn уже установлен, он предложит:
- **обновить** — ключи, настройки и подключения сохранятся (только для той же роли);
- **переустановить начисто** — удалить всё и поставить заново;
- **отменить**.

| | |
|---|---|
| `install.sh reinstall` или `xvpn reinstall` | удалить и поставить заново в той же роли |
| `install.sh uninstall` или `xvpn uninstall` | полностью удалить xvpn, Xray и свои настройки nginx |

Перед удалением установщик сохраняет настройки и базу ключей в `/root/xvpn-backup-ДАТА.tar.gz`. После переустановки сервера-выхода или моста код подключения меняется: на главном сервере удалите старую запись командой `xvpn server del ИМЯ` и добавьте новый код.

Ответить на вопросы заранее можно переменными: `REINSTALL=update|clean|no`, а для удаления `YES=1`.

### Установка без вопросов

Все ответы можно передать переменными. Это удобно, когда серверов много:

```bash
# сервер-выход без домена
DOMAIN= NODE_NAME=nl-2 SNI_TCP=www.samsung.com SNI_XHTTP=www.nvidia.com AGENT_PORT=8443 \
  bash <(curl -fsSL https://raw.githubusercontent.com/duboshin52/xvpn/main/install.sh) node
# мост
NODE_NAME=ru-2 SNI_TCP=ya.ru AGENT_PORT=8443 \
  bash <(curl -fsSL https://raw.githubusercontent.com/duboshin52/xvpn/main/install.sh) bridge
```

Чтобы выход был с доменом, добавьте `DOMAIN=nl2.ваш-домен CF_API_TOKEN=…`.

## Схемы

### 1. Один сервер

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/duboshin52/xvpn/main/install.sh) server
```

- **Без домена.** Reality и XHTTP-Reality на порту 443. Каждому ключу выдаются ссылки и QR-код.
- **С доменом в Cloudflare.** Добавляются XHTTP через CDN (IP сервера скрыт) и ссылка-подписка, по которой клиент обновляет все серверы сам.
- **Бот.** На вопрос «Подключить Telegram-бота?» ответьте «да». Если домена нет, бот работает только командами. С доменом появляется мини-апп.

```bash
xvpn add mama 30 50      # ключ на 30 дней и 50 ГБ
xvpn show mama           # ссылки, подписка, QR в терминале
xvpn list
```

### 2. Несколько серверов

Сначала поставьте главный сервер (схема 1), потом на каждом следующем выполните:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/duboshin52/xvpn/main/install.sh) node
```

В конце установщик покажет код. Добавьте его на главном сервере:

```bash
xvpn server add <код>
```

Можно и через мини-апп: «Серверы» → «Добавить сервер». Все ключи появятся на новом сервере за минуту, и он попадёт в подписки.

- **Сервер без домена.** Агент слушает TCP 8443 по TLS с самоподписанным сертификатом. Главный сервер проверяет его по отпечатку из кода, поэтому подмену заметит. Порт 8443 лучше открыть только для IP главного сервера.
- **Сервер только с IPv6.** Установщик на время установки включит DNS64, чтобы скачать Xray с GitHub, а для выхода на IPv4-сайты настроит Cloudflare WARP.

### 3. Каскад через Россию (белые списки)

Схема: клиент → российский мост → европейские серверы → интернет.

```
клиент ──Reality (SNI ya.ru)──▶ мост RU ──┬──▶ NL-1 (XHTTP-Reality / Reality) ──▶ интернет
                                         ├──▶ DE-1 (XHTTP-Reality / Reality)
                                         └──▶ .ru / .рф / geoip:ru — напрямую
```

1. Главный сервер и выходы ставятся как в схемах 1 и 2.
2. На российском VPS (Yandex Cloud, VK Cloud…) выполните:
   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/duboshin52/xvpn/main/install.sh) bridge
   ```
3. Код моста добавьте на главном сервере: `xvpn server add <код>`.

После этого:
- все серверы-выходы автоматически становятся выходами моста, с каждого по два пути (XHTTP-Reality и Reality-TCP);
- мост проверяет пути каждые 30 секунд и ведёт трафик через самый быстрый живой, при падении выхода переключается сам;
- каскад стоит первым в подписке каждого ключа, прямые серверы остаются в ней запасным вариантом.

Не использовать сервер выходом: `xvpn server cascade NL-1 off`. Убрать прямые ссылки на сервер из подписок, оставив его выходом: `xvpn server hide NL-1`.

В группе безопасности облака откройте TCP 443 для клиентов и TCP 8443 для главного сервера. IP моста проверьте с мобильного интернета при включённых белых списках до того, как раздавать ключи.

### 4. Два моста (резерв входа)

Поставьте мост на два российских VPS, лучше у разных провайдеров (например, Yandex Cloud и VK Cloud), и добавьте оба кода на главном сервере. Оба моста попадут в подписку. Если один заблокируют, клиенты с автовыбором сервера (Hiddify, Happ) переключатся на второй сами, в остальных второй мост выбирают вручную.

### 5. Вход через российский CDN (Yandex Cloud CDN и др.)

Ещё один вход для белых списков, без отдельного российского VPS: клиент → CDN (адреса российских CDN обычно есть в белых списках) → ваш европейский сервер.

1. В DNS заведите две записи без проксирования Cloudflare (серое облако):
   - `origin.ваш-домен` — A-запись на сервер;
   - `cdn.ваш-домен` — CNAME на CDN-ресурс (адрес CNAME покажет CDN после создания ресурса).
2. На сервере выполните `xvpn rucdn`. Скрипт выпустит сертификат Let's Encrypt для `origin.…` и включит приём XHTTP от CDN.
3. В CDN создайте ресурс со следующими настройками:
   - источник `origin.ваш-домен`, протокол HTTPS, заголовок Host `origin.ваш-домен`;
   - доменное имя `cdn.ваш-домен` с TLS-сертификатом (в Yandex Cloud это Let's Encrypt из Certificate Manager);
   - **кеширование выключено**, методы GET, HEAD и OPTIONS.
4. На главном сервере выполните `xvpn sync`, и в подписках появятся ссылки «РФ-CDN».

Российские CDN режут POST, поэтому ссылки используют XHTTP в режиме `packet-up`, а данные отправляют GET-запросами в заголовках. Нужны свежие клиенты (Happ, v2rayN, v2RayTun) с поддержкой параметра `extra`. Учтите, что российский провайдер CDN видит, на какой сервер и сколько трафика идёт. Выключить: `xvpn rucdn off`. Отправка идёт пакетами до 1500 байт, поэтому она заметно медленнее скачивания.

## Команда xvpn

| | |
|---|---|
| `xvpn list` | все ключи |
| `xvpn add ИМЯ [ДНЕЙ] [ГБ]` | новый ключ (0 — бессрочно / безлимит) |
| `xvpn show ИМЯ`, `xvpn qr ИМЯ [N]` | ссылки, подписка, QR-код |
| `xvpn extend ИМЯ ДНЕЙ`, `forever`, `limit ИМЯ ГБ`, `reset` | срок и трафик |
| `xvpn off`, `on`, `rename`, `regen`, `del` | управление ключом |
| `xvpn servers` | серверы, роли, живость выходов каждого моста с пингом |
| `xvpn server add КОД [ИМЯ]`, `server del` | подключить или убрать сервер |
| `xvpn server cascade ИМЯ on/off`, `server hide/show ИМЯ` | роль выхода, видимость в подписках |
| `xvpn server rename ИМЯ НОВОЕ` | переименовать сервер |
| `xvpn rucdn [off]` | вход через российский CDN на этом сервере |
| `xvpn cdn on/off` | XHTTP через Cloudflare в подписках: в России Cloudflare часто замедляют, тогда выключите |
| `xvpn status`, `xvpn sync` | состояние сервисов, синхронизация |
| `xvpn code` | код подключения этого сервера |
| `xvpn update` | обновить xvpn и Xray (на любом сервере) |
| `xvpn reinstall`, `xvpn uninstall` | переустановить начисто или удалить (с резервной копией) |

## Cloudflare (если есть домен)

Остальное установщик сделает сам через API: DNS-запись с проксированием (A, а для IPv6-only AAAA), SSL Full (strict), gRPC и Origin-сертификат на 15 лет. Закрытый ключ создаётся на сервере и никуда не отправляется.

Токен: https://dash.cloudflare.com/profile/api-tokens → **Create Token** → **Create Custom Token** с правами Zone → Zone → Read, Zone → DNS → Edit, Zone → Zone Settings → Edit, Zone → SSL and Certificates → Edit. В Zone Resources выберите свой домен. Токен на сервере не сохраняется. Если нажать Enter вместо токена, установщик попросит вставить сертификат вручную.

Для каждого сервера с доменом нужен свой поддомен, например `nl.ваш-домен`.

## Мини-апп

Каждый сервер нарисован котом. Довольный кот значит, что всё работает, спящий — нет связи. Мост рыжий. На главной показана схема каскада: от моста к выходам тянутся нитки с пингом. Тема светлая или тёмная, как в Telegram.

- **Каскад**: какой выход сейчас используется, сколько в резерве, пинг каждого выхода.
- **Статус**: CPU, RAM, диск, аптайм, состояние Xray, перезапуск Xray, онлайн-ключи, трафик.
- **Ключи**: создать с лимитом и сроком, продлить, сбросить трафик, выключить, перевыпустить, удалить. У каждого ключа есть QR-код и подписка.
- **Серверы**: добавить по коду, переключатель «Выход для каскада», скрыть из подписок. Это может только владелец.
- **Админы**: владелец добавляет админов по Telegram ID. Админ управляет ключами, но не серверами.

Ключи с истёкшим сроком или исчерпанным лимитом отключаются автоматически раз в минуту. Админы получают уведомление об этом, а также о падении и восстановлении серверов.

Команды бота: `/start`, `/status`, `/keys`, `/newkey имя [дней] [ГБ]`, `/admins`, `/addadmin ID [имя]`, `/deladmin ID`, `/id`.

## Советы против обрывов

- При белых списках на мобильном работает только каскад, остальное — запасные варианты для домашнего интернета.
- SNI для Reality берите на сайте с TLS 1.3 и HTTP/2, который хостится рядом с VPS. Проверка: `xray tls ping сайт.com`. Для моста подойдёт сайт из белого списка (ya.ru, vk.com).
- Сменить SNI: отредактируйте `/etc/xvpn/node.env` и выполните `xvpn update`. Ключи сохранятся. Затем на главном сервере нажмите «Обновить параметры» в мини-аппе или выполните `xvpn sync`.
- Установщик включает BBR.

## Где что лежит

- `/etc/xvpn/`: настройки и секреты (`node.env`, `panel.env`), сертификаты.
- `/opt/xvpn/agent/`: агент сервера. `/opt/xvpn/panel/`: главный сервер и база `xvpn.db`, которую стоит бэкапить.
- Сервисы: `xray`, `xvpn-agent`, `xvpn-panel` (только на главном), `nginx`. Логи: `journalctl -u xvpn-panel -f`.
