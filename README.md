# xvpn

Свой VPN на Xray-core с Telegram-ботом и мини-аппом. Не зависит ни от чьих токенов: Xray ставится официальным скриптом XTLS, весь остальной код лежит в этом архиве.

## Что поднимается на каждом сервере

| Протокол | Как идёт трафик | Зачем |
|---|---|---|
| VLESS + XHTTP + TLS | клиент → Cloudflare → ваш сервер | основной: IP сервера скрыт за CDN, трафик похож на обычный HTTPS |
| VLESS + Reality + Vision | клиент → IP сервера:443 | резерв: самый быстрый, не зависит от Cloudflare |
| VLESS + XHTTP + Reality | клиент → IP сервера:443 | резерв: XHTTP без CDN |

Все три протокола работают на порту 443: nginx разводит подключения по SNI.

## Подготовка в Cloudflare

Домен должен быть добавлен в Cloudflare. Остальное установщик сделает сам через API: A-запись с проксированием, SSL Full (strict), gRPC и Origin-сертификат на 15 лет. Закрытый ключ создаётся на сервере и никуда не отправляется.

Нужен API-токен: https://dash.cloudflare.com/profile/api-tokens → **Create Token** → **Create Custom Token**, права:
- Zone → Zone → Read
- Zone → DNS → Edit
- Zone → Zone Settings → Edit
- Zone → SSL and Certificates → Edit

В Zone Resources выберите свой домен. Токен вводится при установке и на сервере не сохраняется. Без токена (нажать Enter) установщик попросит вставить сертификат вручную.

Для второго сервера используйте свой поддомен, например `nl.ваш-домен`.

## Установка (Ubuntu 22.04/24.04, root)

**Главный сервер** (Xray + бот + панель):
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/duboshin52/xvpn/main/install.sh) panel
```
Установщик спросит домен, SNI для Reality, токен Cloudflare, токен бота (от @BotFather) и ваш Telegram ID (узнать у @userinfobot). Потом откройте бота, нажмите /start → «Открыть панель».

**Дополнительный сервер**:
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/duboshin52/xvpn/main/install.sh) node
```
В конце установщик выведет URL агента и секрет. Их нужно вставить в мини-апп: «Серверы» → «Добавить». Повторно показать эти данные: `bash /opt/xvpn/src/install.sh info`.

**Обновление** (код, Xray, зависимости): та же команда с `update` вместо `panel`.

**Без вопросов**: ответы можно передать переменными, например `DOMAIN=vpn.site.ru CF_API_TOKEN=... BOT_TOKEN=... OWNER_ID=... bash <(curl ...) panel`.

## Каскад через панель (мост на российском VPS)

Если у вас стоит панель, мост ставится как ещё один сервер. Все ноды из панели автоматически становятся его выходами.

```
клиент ──Reality (SNI ya.ru)──▶ мост RU ──┬──▶ NL-1 (XHTTP-Reality / Reality) ──▶ интернет
                                         ├──▶ DE-1 (XHTTP-Reality / Reality)
                                         └──▶ .ru / .рф / geoip:ru — напрямую
```

На российском VPS (root), домен и Cloudflare не нужны:
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/duboshin52/xvpn/main/install.sh) bridge
```
В конце установщик покажет **код подключения**. В мини-аппе откройте «Серверы» → «Добавить сервер» и вставьте код. Панель проверит сертификат агента по отпечатку из кода и сама:
- раздаст мосту выходы. С каждой ноды их два (XHTTP-Reality и Reality-TCP), мост выбирает самый быстрый живой (leastPing, проверка каждые 30 секунд);
- заведёт на нодах служебного пользователя для моста;
- поставит каскад первым в подписке каждого ключа.

В группе безопасности облака откройте TCP 443 для клиентов и TCP 8443 для агента. 8443 лучше открыть только для IP сервера с панелью. Чтобы нода не работала выходом, выключите у неё «Выход для каскада». Если её надо скрыть только из подписок, используйте «Скрыть из подписок»: выходом она при этом останется.

## Каскад без панели: `cascade.sh` (Россия → Европа)

Клиент подключается к российскому серверу (например, Yandex Cloud: его IP есть в белых списках мобильных операторов), тот пересылает трафик на зарубежный. Российские сайты открываются напрямую с российского сервера. Скрипт `cascade.sh` работает отдельно от панели.

```
клиент ──VLESS+Reality+Vision (SNI ya.ru)──▶ RU-сервер ──VLESS+XHTTP+Reality──▶ EU-сервер ──▶ интернет
                                                │
                                                └──▶ .ru / .рф / geoip:ru — напрямую
```

**1. Зарубежный сервер** (Ubuntu, root):
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/duboshin52/xvpn/main/cascade.sh) exit
```
В конце скрипт выведет ссылку `vless://…`, она нужна для шага 2. Если на сервере уже стоит нода xvpn, этот шаг не нужен: создайте в панели ключ `ru-bridge` и возьмите его ссылку Reality или XHTTP-Reality.

Если у сервера только IPv6, скрипт сам временно включит DNS64, чтобы скачать Xray с GitHub, и настроит Cloudflare WARP для выхода на IPv4-сайты. У российского сервера в этом случае тоже должен быть IPv6.

**2. Российский сервер** (Ubuntu, `sudo -i`):
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/duboshin52/xvpn/main/cascade.sh) bridge
```
Скрипт спросит ссылку из шага 1, SNI (по умолчанию `ya.ru`, это должен быть сайт из белого списка) и имя первого клиента. Потом покажет ссылку клиента и QR-код. В группе безопасности облака откройте TCP 443.

**Резервирование выходов.** Если зарубежных серверов несколько, запустите `exit` на каждом и при установке моста вставьте все ссылки по очереди. Мост проверяет выходы каждые 30 секунд и ведёт трафик через самый быстрый из живых. Если выход падает, трафик через несколько секунд уходит на другой, клиенту ничего переключать не нужно.

```
                         ┌──▶ EU-1 ──┐
клиент ──▶ RU-сервер ────┤  (самый быстрый живой) ├──▶ интернет
                         └──▶ EU-2 ──┘
```

**Управление** (на российском сервере):
```bash
xvpn-cascade exit-add 'vless://…' [ИМЯ]   # добавить выход
xvpn-cascade exit-del ИМЯ                 # убрать выход
xvpn-cascade check                        # проверить каждый выход
xvpn-cascade add ИМЯ    # новый клиент
xvpn-cascade del ИМЯ    # удалить клиента
xvpn-cascade links      # показать ссылки
xvpn-cascade update     # обновить Xray
```
Ответы на вопросы можно передать переменными: `UPSTREAM='vless://…' SNI=ya.ru CLIENT=phone bash <(curl …) bridge`.

## Мини-апп

Каждый сервер нарисован котом. Довольный кот значит, что всё работает, спящий — нет связи. Мост рыжий. На главной показана схема каскада: от моста к выходам тянутся нитки с пингом. Тема светлая или тёмная, как в Telegram.

- **Каскад**: какой выход сейчас используется, сколько в резерве, пинг каждого выхода и живость обоих путей.
- **Статус**: CPU, RAM, диск, сеть, аптайм, состояние Xray на каждом сервере, перезапуск Xray, число онлайн-ключей, общий трафик.
- **Ключи**: создать ключ с лимитом ГБ и сроком; продлить, сбросить трафик, выключить, перевыпустить, удалить. У каждого ключа есть QR-код и ссылка-подписка, отдельные vless-ссылки тоже доступны.
- **Серверы**: добавить, удалить, скрыть сервер из подписок. Это может только владелец.
- **Админы**: владелец добавляет и убирает админов по Telegram ID. Админ управляет ключами, но не серверами и не другими админами.

Ключи, у которых кончился срок или лимит трафика, отключаются автоматически раз в минуту. Админы получают уведомление об этом, а также о падении и восстановлении серверов.

## Бот

`/start`, `/status`, `/keys`, `/newkey имя [дней] [ГБ]`, `/admins`, `/addadmin ID [имя]`, `/deladmin ID`, `/id`.

## Подписка

Одна ссылка на ключ содержит все серверы и все три протокола. Она работает в Happ, Hiddify, v2rayN и v2RayTun. Клиенты, которые это поддерживают, показывают остаток трафика и срок действия.

## Советы против обрывов

- По умолчанию используйте XHTTP-CDN. Если Cloudflare в вашем регионе тормозит, переключайтесь на Reality.
- В качестве SNI для Reality берите сайт с TLS 1.3 и HTTP/2, который хостится рядом с вашим VPS (та же страна или провайдер). Проверить сайт: `xray tls ping сайт.com`. Сменить SNI: отредактируйте `/etc/xvpn/node.env` и выполните команду установки с `update`. Ключи сохранятся. Затем в панели: «Серверы» → «Обновить параметры».
- Установщик включает BBR.

## Где что лежит

- `/etc/xvpn/`: настройки, сертификат и секреты (`node.env`, `panel.env`).
- `/opt/xvpn/agent/`: агент ноды. `/opt/xvpn/panel/`: панель, бот и база `xvpn.db` (её стоит бэкапить).
- Сервисы: `xray`, `xvpn-agent`, `xvpn-panel`, `nginx`. Логи: `journalctl -u xvpn-panel -f`.
